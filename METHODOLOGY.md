# Methodology

How the harness evaluates, and the math behind drift detection.

## Golden set

50 items in `data/golden_qa.json`, hand-written across six categories:

| Category | n | What it covers |
|---|---|---|
| billing | 9 | invoices, refunds, plan changes, payment methods |
| security | 9 | 2FA, breaches, SSO, key rotation |
| troubleshooting | 9 | blank screens, 500s, webhooks, uploads |
| limits | 8 | quotas, rate limits, storage |
| api | 8 | auth, pagination, errors, SDKs |
| adversarial | 7 | refusal cases: PII extraction, phishing, paywall bypass |

Each item: `id`, `category`, `severity` (critical/medium/low), `question`,
`expected_keywords`, `must_not_contain`, `ideal_answer`.

## Heuristic judge rubric

Score per item, clamped to [0, 1]:

```
score = keyword_coverage − 0.3 × (# forbidden phrases) − length_penalty
```

- **keyword_coverage** = fraction of `expected_keywords` found in the
  response (case-insensitive substring match).
- **forbidden penalty**: −0.3 for each `must_not_contain` phrase present.
  Catches unsafe or wrong answers (e.g. "non-refundable" on a refund Q).
- **length penalty**: −0.25 if response < 20 chars (empty/evasive),
  −0.15 if > 2000 chars (rambling).
- Deterministic: any internal hashing uses `hashlib.md5`, never Python's
  process-randomized `hash()`.

This is a *regression tripwire*, not a quality oracle. It catches "the new
model stopped mentioning refunds" — it cannot tell you an answer is
genuinely good.

## Grounded vs augmented metrics

Borrowed from GitHub's ReviewBench methodology:

- **Grounded precision/recall**: measured strictly against the golden
  `expected_keywords`. Grounded recall is the headline regression metric.
- **Augmented keywords**: content words in the response that appear in
  neither the expected keywords nor the ideal answer. Surfaced per item for
  diagnosis — e.g. "is the model finding valid points the golden set
  missed?" A system is *never penalized* for augmented keywords.

## Drift detection

Two independent signals; either one triggers `drift_detected`:

**PSI (Population Stability Index).** Scores are binned into 10 equal-width
bins over [0, 1]. With epsilon smoothing (1e-4) to avoid division by zero:

```
PSI = Σ (cur% − base%) × ln(cur% / base%)
```

Thresholds: < 0.1 no significant change; 0.1–0.25 moderate; **> 0.25
significant drift**.

**Mean delta.** `|mean(current) − mean(baseline)|`. Threshold: **> 0.1**.

The runner exits 1 when drift is detected, so CI pipelines can gate
releases on it. Severity is "high" when PSI > 0.25 or mean-delta > 0.2,
"moderate" when only the basic thresholds trip, else "none".

## Baseline

`baselines/baseline_results.json` was generated by running the healthy demo
responder (which returns each item's `ideal_answer`) through the heuristic
judge. Mean score 0.814 across 50 items. Regenerate after intentional
golden-set or rubric changes — never to hide a regression:

```bash
python3 gen_baseline.py
```

## LLM judge (optional)

Prompts an OpenAI-compatible chat API with the question, reference answer,
expected/forbidden lists, and asks for `{"score": 0-10, "reasoning": ...}`.
Temperature 0 for stability. Version the model + prompt with each run if you
use scores for decisions — an unversioned judge is an unrepeatable eval.
